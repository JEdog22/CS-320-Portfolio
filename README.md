# CS-320-Portfolio
CS 320 Portfolio Submission

Project Description

This project was developed for SNHU's CS 320 course and focuses on creating and testing a Java Contact Service. The project includes Contact.java, which manages contact information and validates required fields, and ContactService.java, which manages contact records. The accompanying JUnit test files, ContactTest.java and ContactServiceTest.java, verify that the code meets requirements, handles valid and invalid input, prevents duplicate contact IDs, and correctly adds, updates, and deletes contacts.

Reflection Questions

How can I ensure that my code, program, or software is functional and secure?

I can ensure my software is functional and secure by testing it regularly, checking that it meets the requirements, and validating user input. Using JUnit tests helps me identify errors and verify that the program handles both valid and invalid information correctly. I can also use boundary-value testing to check limits and exception testing to confirm that invalid input is rejected. Reviewing my code and running tests after making changes helps me maintain reliable software and prevent defects.

How do I interpret user needs and incorporate them into a program?

I interpret user needs by carefully reviewing the requirements and identifying what the program must accomplish. I then translate those requirements into code and test cases. For the Contact Service, this meant ensuring that contact information followed specific rules, including unique contact IDs, required fields, character limits, and valid phone numbers. Testing these requirements helped me verify that the program behaved as expected instead of relying on assumptions.

How do I approach designing software?

I approach software design by breaking a problem into smaller components and determining the responsibilities of each component. In the Contact Service, the Contact class manages contact information and validation, while the ContactService class handles operations on contact records. Separating these responsibilities makes the code easier to understand, test, and maintain. I also consider the requirements early in the design process and use testing to identify problems and improve the quality of the software.
